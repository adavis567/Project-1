Campus Resource Reservation System

Algorithm Complexity Analysis

This document describes the time complexity of the main operations used in the Campus Resource Reservation System.

1. Resource Searching

Algorithm: Linear Search

Time Complexity: O(n)

The program checks resources one at a time until it finds the requested resource ID or reaches the end of the resource collection.

In the worst case, every resource must be checked.

2. Reservation Searching

Data Structure: Linked List

Time Complexity: O(n)

The program traverses the active reservation linked list to locate a reservation by ID. In the worst case, it must examine every node.

3. Resource Sorting

Algorithm: Merge Sort

Time Complexity: O(n log n)

Merge Sort divides the resource collection into smaller sections, sorts those sections, and merges them into sorted order.

The algorithm has O(n log n) time complexity in the best, average, and worst cases when implemented in its standard form.

4. Reservation Insertion

Data Structure: Linked List

Time Complexity: O(n) if the program traverses the list to find the insertion position; O(1) if insertion occurs directly at a known position, such as the head.

The actual complexity depends on how the reservation manager inserts new nodes.

5. Reservation Removal

Data Structure: Linked List

Time Complexity: O(n)

The program may need to traverse the linked list to locate the reservation that must be removed. Once the node and its predecessor are located, unlinking the node takes O(1) time.

6. Waiting-List Insertion

Data Structure: Queue

Time Complexity: O(1)

A queue that maintains a rear pointer can add a new student to the end of the queue in constant time.

7. Waiting-List Removal

Data Structure: Queue

Time Complexity: O(1)

Removing the student at the front of a linked queue takes constant time when the queue maintains a front pointer.

8. Cancellation History Insertion

Data Structure: Stack

Time Complexity: O(1)

Adding a cancelled reservation to the top of a stack takes constant time.

9. Undo Cancellation

Data Structure: Stack

Time Complexity: O(1) for removing the top stack entry. Restoring the reservation may require additional time if the program searches for a resource or checks other records.

10. Resource Inventory Storage

Data Structure: Vector

Access by Index: O(1)

Search by ID: O(n)

A vector supports constant-time access by index. Finding a resource by ID requires a linear scan unless another search structure is used.

Summary

Operation	Algorithm or Data Structure	Time Complexity
Resource search	Linear search	O(n)
Reservation search	Linked list traversal	O(n)
Resource sorting	Merge Sort	O(n log n)
Reservation insertion	Linked list	Depends on insertion method
Reservation removal	Linked list	O(n)
Waiting-list insertion	Queue	O(1)
Waiting-list removal	Queue	O(1)
Cancellation history insertion	Stack	O(1)
Undo cancellation	Stack operation	O(1) for stack removal; restoration may take longer
Resource access by index	Vector	O(1)
Resource search by ID	Vector scan	O(n)
